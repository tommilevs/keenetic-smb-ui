keenetic-smb-ui — собственный SMB-сервер с веб-панелью для роутеров Keenetic на Entware. Ставится обычным .ipk, поднимает отдельный Samba рядом со штатным SMB и собирает в одну шару диски Proxmox и USB-диски роутера.

Зачем это нужно

Штатный SMB Keenetic занимает 192.168.165.1:445: его нельзя перевесить на другой адрес, он не умеет агрегировать хранилища и раздавать диски Proxmox. Приложение поднимает второй, независимый SMB на отдельном IP — встроенный сервер продолжает работать как раньше, оба живут одновременно.

Внутри — Samba 4.24 из Entware со своими конфигом, pid- и state-каталогами, поэтому NDMS ничего не замечает и не конфликтует.

Возможности

  • Отдельный IP и интерфейс для SMB (например 192.168.160.2 на br0), алиас /32 приложение вешает само.
  • Агрегированная шара: внешние SMB-шары (Proxmox) и USB-диски роутера в одном дереве \\IP\all.
  • Подкаталог у диска: можно подключить не всю шару, а конкретную папку — как поле «Подкаталог» при добавлении SMB-хранилища в Proxmox.
  • Права на папки с наследованием, как в Keenetic: для каждого пользователя «Запрещён / Чтение / Чтение и запись», правило «наследуется» или «только здесь».
  • Пользователи: свои аккаунты и импорт из роутера одной кнопкой (ndmc -c "show user").
  • Веб-панель на встроенных файлах (без CDN): обзор, SMB-сервер, диски, пользователи, доступ к папкам, статистика с графиками, логи, настройки, автообновление.
  • Статистика: load average, память, трафик, SMB-сессии, занятость дисков и история для графиков.
  • Обновление из панели: проверка GitHub Releases, скачивание нужного .ipk, установка через opkg и перезапуск службы.
  • Один статический бинарник без cgo; пакеты под aarch64, armv7, mips, mipsle, i386, x86_64.

Разделы панели

  • Обзор — состояние сервера, шара, сессии, трафик, графики нагрузки, занятость дисков.
  • SMB-сервер — IP, бридж, рабочая группа, имя сервера, имя и путь шары, порты, протоколы, гость, «только чтение», force user, дополнительные строки smb.conf, старт/стоп/рестарт и просмотр конфига.
  • Общие диски — CRUD внешних шар, вкл/выкл, флаг «только чтение», подкаталог, живой статус монтирования.
  • Пользователи — аккаунты SMB, пароль и «только чтение», импорт из NDMS.
  • Доступ к папкам — матрица «папки × пользователи» с наследованием.
  • Статистика / Логи / Настройки — метрики, хвост samba.log, учётные данные панели, интервал статистики, обновления.

Установка

opkg update
opkg install samba4-server samba4-client

# busybox wget на Keenetic без TLS — качаем curl'ом
curl -fsSL -O https://github.com/tommilevs/keenetic-smb-ui/releases/latest/download/keenetic-smb-ui_1.3.4_aarch64-3.10.ipk
opkg install ./keenetic-smb-ui_1.3.4_aarch64-3.10.ipk

После установки панель доступна на http://<ip-роутера>:8099, логин admin, пароль lip368lip (меняется в «Настройках»).

Можно подключить и как opkg-фид — в каждом релизе лежат Packages и Packages.gz:

echo "src/gz keenetic-smb-ui https://github.com/tommilevs/keenetic-smb-ui/releases/latest/download" >> /opt/etc/opkg.conf
opkg update
opkg install keenetic-smb-ui

Подключение дисков Proxmox

В разделе «Общие диски» добавляется строка: имя, хост, шара, (необязательно) подкаталог, логин, пароль, вкл, «только чтение». Приложение монтирует шару в агрегированное дерево и переэкспортирует её клиентам.

На хосте Proxmox шара должна быть отдана аккаунту, который использует роутер; если каталог принадлежит root, помогает force user = root в smb.conf — иначе диск логично пометить «только чтение».

Подробная пошаговая инструкция с примером трёх хостов: docs/proxmox-disks.ru.md.

Права на папки

Каждая папка с правилами публикуется отдельной SMB-шарой, а внутри используется read only = yes + явный write list, поэтому ограничения делает сам Samba — POSIX ACL и xattr на смонтированных CIFS-дисках не нужны.

  • уровни: «Запрещён», «Чтение», «Чтение и запись»;
  • правило «наследуется» действует на вложенные папки, пока там нет своего правила;
  • варианты «только здесь» ограничивают правило одной папкой;
  • проверено: admin пишет в папку, vms видит её только на чтение, а при «Запрещён» получает NT_STATUS_ACCESS_DENIED.

Проверено на практике

  • Keenetic (aarch64, Entware, ядро 4.9-ndm): свой smbd на 192.168.160.2:445 рядом со штатным SMB.
  • Три внешних диска Proxmox в одной шаре, включение/выключение и «только чтение» из панели.
  • Импорт пользователей из NDMS и вход по ним в шару.
  • Обновление 0.8.0 → 0.8.1 прямо из панели через GitHub Releases.
  • Остальные архитектуры собираются, но на реальных устройствах пока не запускались.
