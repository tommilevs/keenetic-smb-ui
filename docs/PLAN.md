# keenetic-smb-ui — план работ

Цель: приложение на роутере (Entware), поднимает **свой** Samba 4 на отдельном
IP (`192.168.160.2:445`), агрегирует диски Proxmox и локальные USB-диски в одну
шару, даёт веб-панель с широкими настройками, статистикой и логами; ставится и
обновляется через `opkg install` из GitHub Releases.

## Фаза 1 — каркас (сделано)

- [x] Go-приложение без внешних зависимостей, один статический бинарник.
- [x] Конфиг `/opt/etc/keenetic-smb-ui/config.json` (атомарная запись, дефолты).
- [x] Генерация `smb.conf` (свой state/lock/pid/private — NDMS SMB не трогаем).
- [x] Управление smbd (`-D --configfile`), пользователи через `smbpasswd`.
- [x] Привязка IP: `ip addr add <IP>/32 dev <iface>` при старте.
- [x] Агрегация: монтирование внешних CIFS-шар, симлинки на `/tmp/mnt/*`.
- [x] Статистика `/proc` (load, mem, net, сессии smbstatus, диски, история).
- [x] Веб-API + встроенная панель (RU): обзор, сервер, диски, пользователи,
      статистика, логи, настройки. Basic Auth, режим «только чтение».
- [x] Кросс-сборка: arm64, arm(v7), mips, mipsle, mips64le, 386, amd64.
- [x] Каркас `.ipk` (control, init.d, config.default).
- [x] AGPL-3.0 + NOTICE с обязательной атрибуцией.

## Известные решения

- Samba ставится из Entware (`samba4-server`), приложение его не заменяет:
  панель генерирует конфиг и следит за процессом. С версии 1.5.0 копии
  `samba4-server`, `samba4-client` и всех зависимостей лежат в нашем релизе,
  поэтому установка не зависит от доступности фида Entware (см. `scripts/vendor-deps.ps1`).
- Свои state/pid/private каталоги → нативный SMB на `192.168.160.1:445`
  остаётся нетронутым, оба сервера живут одновременно.
- Монтирование внешних шар — `cifs`, свой набор опций (`actimeo=10`,
  `retrans=3`, `nomapposix`) против «фантомных» dentry.
